# 시작하기 — 하네스와 컨벤션의 기초

[← README](../README.md) · 다음: [환경 준비](environment.md)

이 문서는 AI 코딩 에이전트를 처음 쓰는 사람(비전공자·입문자·바이브코더)을 위한 출발점이에요. 하네스가 무엇인지, 컨벤션이 왜 필요한지, SimpleHarness로 내 저장소에 하네스를 넣는 순서를 설명해요.

## 1. 하네스란

AI 코딩 에이전트(Claude Code, Codex)는 한 세션이 끝나면 그 세션에서 배운 규칙을 기억하지 못해요. 새 세션은 저장소에 있는 문서와 설정만 보고 시작하고, 문서에 없는 부분은 모델이 스스로 채워요. 그래서 같은 요청에도 세션마다 다른 구조, 다른 이름, 다른 검사 방법이 나와요.

**하네스(harness)** 는 에이전트를 프로젝트 규칙에 묶는 장치예요. 말에 씌우는 마구처럼, 에이전트가 움직이는 방향을 정하고 벗어나면 멈춰 세워요. SimpleHarness가 만드는 하네스는 다섯 부분으로 이루어져요.

| 부분 | 역할 | 생성 위치 |
| --- | --- | --- |
| 에이전트 문서 `AGENTS.md` | **뇌** — 요청을 받으면 무엇을 어떤 순서로 하고, 언제 무엇을 금지하는지 정하는 행동 계약 | 저장소 루트 |
| 훅(hook) | **제어자** — 에이전트가 도구를 부르거나 답변을 끝내는 순간마다 실행돼서, 규칙 위반을 차단하고 지켜야 할 조건을 주입 | `.harness/hooks/run_project_hook.mjs` + 에이전트별 등록 파일 |
| 스킬(skill) | **팔다리** — 행동 하나를 실제로 수행하는 상세 절차. 명세·논리·규칙·좋은 예시·나쁜 예시를 담음 | Claude `.claude/skills/`, Codex `.agents/skills/` |
| 컨벤션 `docs/conventions.md` | **방향 선언** — 프로젝트의 목적·정의·확정 결정을 조항(C00~C20)으로 선언한 단일 기준 | `docs/` |
| AI 트래킹 `docs/ai-tracking.md` | **추적** — 진행 기록, 완료 세션 요약, 프로젝트 노드(폴더·계층) 관리 | `docs/` |

연결 방향은 하나예요: **컨벤션(무엇을·왜) → AGENTS(어떤 순서로) → 스킬(어떻게) → 도구 → 결과**. 훅은 이 연결이 실제 도구 호출에서 지켜지는지 매번 판정해요.

## 2. 컨벤션이란

컨벤션(convention)은 "우리 프로젝트는 이렇게 한다"를 한 곳에 적은 약속이에요. 흔히 코딩 스타일(들여쓰기, 이름 규칙)만 떠올리지만, 이 템플릿의 컨벤션은 더 넓어요.

| 담는 것 | 예시 |
| --- | --- |
| 방향과 목적 | 이 프로젝트가 무엇을 만들고, 무엇을 우선하는가 (C02) |
| 정의 | "FIX"란 원인 소유자를 고치는 것이고 증상 숨기기가 아니다 (C06) |
| 확정 결정 | 기술 스택, 층별 소유자, 데이터 위치 (C02·C03·C17) |
| 구조 | 폴더 배치와 의존 방향, 인라인 금지 같은 핵심 규칙 (C04) |
| 이름 규칙 | 언어별 함수·타입·파일 이름 (C05) |
| 도구 계약 | 어떤 도구를 어떤 방법으로만 쓰는가, 검사 명령과 금지 명령 (C12) |
| 검증 방법 | 빠뜨린 것 0개(정방향), 지어낸 것 0개(역방향)를 증명하는 방법 (C14) |

### 왜 AI에게 컨벤션이 꼭 필요한가

1. **공백은 추측으로 채워져요.** 문서에 "타입은 어디에 둔다"가 없으면 모델은 그때그때 편한 곳에 둬요. 규칙이 문서에 있으면 추측할 공백이 사라져요.
2. **근거를 댈 대상이 생겨요.** 이 하네스는 에이전트가 행동마다 "어느 조항의 어느 행 때문에"를 밝히게 해요. 조항이 있어야 근거가 생기고, 근거가 있어야 사람이 검토할 수 있어요.
3. **규칙과 강제가 연결돼요.** 컨벤션의 규칙 중 기계로 판정할 수 있는 것(예: 인라인 주석 금지, 기존 파일 덮어쓰기 금지)은 훅이 같은 조항 번호를 달고 차단해요. 훅이 막을 때 보여 주는 메시지에도 조항 번호와 설정 키가 들어 있어서, 왜 막혔는지 바로 찾아갈 수 있어요.

### 컨벤션을 읽는 법

- 조항은 `C00`~`C20` 번호와 `<a id="C04"></a>` 같은 앵커를 가져요. 다른 문서는 이 번호로 조항을 가리켜요.
- 생성 직후 컨벤션에는 `(프로젝트 정의` 로 시작하는 행이 있어요. 이 행들은 **사용자가 직접 정하는 결정**이에요. 비워 두면 에이전트는 그 판단을 스스로 내리지 않고 사용자 지시를 기다리는 범위로 다뤄요.
- 컨벤션 맨 앞의 "컨벤션 요약" 표는 조항으로 가는 압축 안내예요. 세션이 압축(compaction)되면 훅이 이 표를 다시 넣어 줘요.

## 3. 빠른 시작

### 3.1 준비물

| 도구 | 쓰임 | 설치 안내 |
| --- | --- | --- |
| Go | SimpleHarness CLI 실행 (`go.mod`: `go 1.26`) | [환경 준비](environment.md#5-도구-설치-명령) |
| Git | 저장소 관리, 커밋 가드 | [환경 준비](environment.md) |
| Node.js | 생성되는 훅·커밋 가드·서브 에이전트 실행기가 Node.js로 실행됨 | [환경 준비](environment.md#5-도구-설치-명령) |
| Claude Code 또는 Codex | 메인 에이전트 | [에이전트별 적용](agents.md) |

### 3.2 CLI 실행

이 저장소를 내려받은 폴더(루트)에서 실행해요.

```sh
go run ./src
```

CLI는 순서대로 물어봐요.

1. **출력 언어** — 한국어 · English · 简体中文. 생성되는 컨벤션·트래킹 문서와 에이전트 응답 언어가 이것으로 정해져요.
2. **환경 점검** — 운영체제(Windows 10/11, macOS, Linux, WSL)를 감지하고 셸 업그레이드·Git·기본 터미널 설정을 단계별로 안내해요.
3. **프로젝트** — 이름, 한 줄 요약, 스킬 접두사, 종류(웹 / 일반 프로그램), 대표 언어(TypeScript·Python·C++(xmake)·Rust·Go·PHP).
4. **에이전트** — 메인 에이전트(Claude Code 또는 Codex)와 서브 에이전트(다른 메인 CLI, Ollama, Ollama Cloud, Alibaba Model Studio, Kimi, Z.ai GLM, DeepSeek, MiniMax, OpenRouter 중 여러 개).
5. **핵심 규칙** — 도메인 기반 구조·명명, 인라인 주석·타입·스타일·이벤트 핸들러·매직 리터럴 금지. 기본값은 모두 켜짐이에요.
6. **생성** — 요약을 확인하면 `output/<프로젝트 이름>/` 폴더에 결과물을 모아요.
7. **추천 도구** — 프로젝트 종류·언어에 맞는 도구(jq, ripgrep, sqlite3, DuckDB, LLVM, GCC, 언어 툴체인 등)를 보여 주고, 원하면 패키지 매니저로 설치해요. 거절하면 설치 명령만 보여 줘요.
8. **다음 단계** — 남은 설정을 번호로 보여 주고 `output/<프로젝트 이름>-SETUP.md` 에도 저장해요.

### 3.3 내 저장소에 넣기

1. `output/<프로젝트 이름>/` 폴더를 열고, 안의 **모든** 파일·폴더를 선택해서 내 저장소 루트로 끌어다 놓아요. `.claude`, `.codex`, `.agents`, `.harness`, `.githooks` 처럼 점으로 시작하는 폴더도 꼭 함께 옮겨요(탐색기에서 숨김 항목 표시를 켜세요).
2. 저장소 루트에서 `git config core.hooksPath .githooks` 를 실행해 커밋 가드를 연결해요.
3. `.gitignore` 에 `tmp-agent/` 를 추가해요(훅 상태·임시 산출물 폴더).
4. `docs/conventions.md` 의 `(프로젝트 정의` 행을 채워요.
5. 에이전트를 다시 시작하고 훅이 등록됐는지 확인해요 → [에이전트별 적용](agents.md), [훅 설정](hooks.md).

## 5. 용어집

| 용어 | 뜻 |
| --- | --- |
| 에이전트 | 터미널·IDE·앱에서 파일을 읽고 고치고 명령을 실행하는 AI. 여기서는 Claude Code와 Codex |
| 메인 / 서브 에이전트 | 메인은 사용자와 대화하며 저장소를 고치는 에이전트, 서브는 메인이 조사·검토·초안을 맡기는 읽기 전용 에이전트 |
| 세션 | 에이전트와 한 번 대화를 시작해서 끝낼 때까지 |
| 컴팩션(compaction) | 대화가 길어져 앞부분을 요약으로 줄이는 것. 요약에서 빠진 규칙은 훅이 다시 넣어 줘요 |
| 훅 이벤트 | `SessionStart`(세션 시작), `UserPromptSubmit`(지시 입력), `PreToolUse`(도구 호출 직전), `PostToolUse`(도구 호출 직후), `Stop`(답변 종료) |
| 스택 | 언어별 검사 묶음. 표지 파일(예: `Cargo.toml`)이 있을 때만 켜져요 |
| 스크래치 폴더 | `tmp-agent/`. 훅 상태, 임시 산출물, 서브 에이전트 작업 파일을 두는 곳 |
| MCP | 에이전트에 외부 도구를 붙이는 표준 연결 방식(Model Context Protocol) |
| 커밋 가드 | 커밋 직전에 막힌 확장자 파일이 섞였는지 검사하는 git 훅 |
